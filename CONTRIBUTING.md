# Contributing

Developer notes for the `cloudconsole` CLI. User-facing documentation is in
[README.md](./README.md).

**The source of truth is the Cloud Console monorepo**, at
`apps/cloudconsole-cli`. The public `studio-ch/cloudconsole-cli` repository is a
mirror, published on each release — send changes to the monorepo, not to
the mirror, or they will be overwritten.

## Build and test

```bash
make build        # -> dist/cloudconsole
make test         # go test ./... -race
make lint         # gofmt + go vet
```

The module is part of the repository's Go workspace (`go.work`), so
`go build ./...` from this directory picks up `edge-agent` and
`tunnel-proto` without any `replace` directives.

## The generated API client

`internal/api/gen/client.gen.go` is generated by `oapi-codegen` from
`api/openapi-3.0.json`, and **both are committed**. That keeps builds
reproducible, independent of a running server, and makes an API surface
change visible in the pull-request diff.

To refresh after the API changes:

```bash
make spec        # re-dump the OpenAPI document from apps/api
make generate    # regenerate the Go client
```

`make spec` imports `apps/api/src/app.ts` directly. It needs neither a
database nor a running server, but it does need `pnpm install` to have
been run at the repository root.

CI runs `make check-generate` as an advisory job and fails it when the
committed client has drifted from the API.

### Why a separate 3.0-labelled document

The API advertises `/v1/openapi.json` as OpenAPI `3.1.0`, but the
document is 3.0-shaped: `@hono/zod-openapi`'s `getOpenAPIDocument()` is
the `OpenApiGeneratorV3` code path and emits `nullable: true`, which is
not a 3.1 keyword. Go's generator stack (`oapi-codegen` on top of
`kin-openapi`) is 3.0-only and refuses the version string while being
perfectly happy with the payload.

Rather than relabel a public document under its existing consumers,
`apps/api/src/app.ts` serves the same bytes a second time at
`/v1/openapi-3.0.json` with an honest version field. A test in
`apps/api/src/app.docs-smoke.test.ts` asserts the two documents stay
identical apart from that field.

### What codegen does not cover

Six endpoints are registered with raw Hono handlers rather than
`.openapi()`, so they never appear in the document and are hand-written
in `internal/api`:

| Endpoint | Client |
|---|---|
| `POST /v1/xcloud/instances/{id}/agent/exec` (NDJSON stream) | `ndjson.go` |
| `POST\|GET /v1/xcloud/instances/{id}/agent/files` | `ndjson.go` |
| `GET /v1/resources/{id}/events` (SSE) | `sse.go` |
| `POST /v1/support/attachments` (streaming multipart) | `upload.go` |
| Presigned `PUT`s from `POST /v1/tenant-uploads/start` | `upload.go` |

## Package layout

| Package | Responsibility |
|---|---|
| `cmd/cloudconsole` | `main`; signal handling and the single `os.Exit` call |
| `internal/cmd` | Cobra command tree, one file per domain |
| `internal/config` | Profiles, XDG paths, 0600 enforcement, precedence |
| `internal/api` | Transport: auth, retries, RFC 9457 errors, tracing |
| `internal/api/gen` | Generated — do not edit |
| `internal/output` | `table` / `wide` / `json` / `yaml` rendering |
| `internal/exitcode` | The public exit-code contract |
| `internal/buildinfo` | Linker-stamped version metadata |

## Invariants worth knowing before changing things

- **`--output json` is the API payload verbatim.** Only one level of the
  `{"data": …}` envelope is unwrapped. No renaming, no computed fields.
  A CLI-owned JSON shape would be a second public schema needing its own
  deprecation cycle.
- **`internal/api/idempotent.go` must track the server.** Only five
  routers mount the `idempotency()` middleware, and the retry policy's
  safety depends on that list being exact. A pinned test fails if it
  changes.
- **A 429 is retryable for every method**, including an unguarded POST,
  because the rate limiter is mounted globally before all routes — the
  request provably never reached a handler.
- **Exit codes are a public contract** from v0.1.0. Never renumber one.
- **Credentials never reach argv.** `auth login` prompts without echo or
  reads `--token-stdin`.

## Testing against a real deployment

```bash
export CLOUDCONSOLE_API_URL=https://api.cloud.cloudbit.ch   # stage
export CLOUDCONSOLE_API_TOKEN=sk_live_...                   # read-only key
./dist/cloudconsole auth status
./dist/cloudconsole version
```
